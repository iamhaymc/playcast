# TODO

High-impact work for Chordcast, most impactful first.

1. **[Infra] Keep one bad request from taking down the server.** `GET /%E0%A4%A` throws a `URIError` from `decodeURIComponent` outside the `try` in `serveFile` (`host.mjs`), and the process exits, ending every room. Catch it and return 400. Also wrap each room's `loop()` in a `try`/`catch`, so a bug in one spell handler closes that match instead of the whole host.
2. **[Gameplay] Add sound.** The game has no audio. Add per-school cast and impact sounds, rune key clicks, fizzle, parry, fall and surge stings, and music for the menus and the fight. Give incoming hostile spells a clear cue: the ward is a timing skill, and sound makes timing much easier to learn. Add gamepad rumble and touch haptics on hits and parries.
3. **[Gameplay] Interactive tutorial and practice room.** Learning chords is the core skill, but new players only get a static guide. Add a guided first match (aim, cast, ward, metamagic, a reaction) and a sandbox with target dummies, no clock and a chosen book, where players can drill chords.
4. **[Infra] Rejoin after a disconnect.** `Link` reconnects, but the host treats it as a new peer, so a bot plays the player's mage until the match ends. Give each peer a resume token (kept in `sessionStorage`) so they can reclaim their seat and mage within about 60 seconds.
5. **[Infra] CI on every PR.** There is no `.github/`. Run the engine and host tests on each push, with the Playwright browser run as its own job, and block merges on red.
6. **[Efficiency] Shrink the frame stream.** Every tick sends the full JSON state. Measured: about 38 KB/s per client in 1v1, 102 KB/s in 4v4 and 181 KB/s in 8v8, or about 2.9 MB/s out of the host for one 8v8 room. Send only the mages and fields that changed, send fixed aura fields once, and turn on `perMessageDeflate`.
7. **[Gameplay] Play with strangers.** The only way to find human opponents is to share a code. Add a public room list or a quick-match queue that seats humans first and fills the rest with bots.
8. **[Efficiency] Production build and caching.** The page loads about 2.5 MB of unminified JS (`three.core.js` 1.46 MB, `three.module.js` 663 KB, plus `page.mjs` and `core.mjs`). It is served without compression and with `cache-control: no-cache`. Bundle and tree-shake with esbuild, minify, serve brotli or gzip, and use hashed file names with immutable caching. Shared links should open fast.
9. **[Gameplay] Data-driven balance.** `simulate()` already exists. Build a harness that runs thousands of bot matches and reports how much each spell, school, metamagic and reaction adds to win rate, and flags outliers. Use it to tune the 137 spells and post its report from CI.
10. **[Graphics] Cut clutter in big fights.** In the 2v2 screenshot, leaves and sparks already cover the mages. At 8v8 they would hide cast bars and incoming spells, the two things players need to read. Draw your own spells and spells aimed at you at full strength, fade the rest, cap particle output per mage, and scale budgets by mage count.
11. **[Organization] Split the big files into modules.** `page.mjs` is 3,945 lines and `core.mjs` is 2,360. Split them along their numbered sections (Sparks, Figure, Stage, Hud… and Codex, Match, Brain, Pilot…), with the spell list in its own data file. The import map already serves modules, so no build step is needed.
12. **[Organization] Static checks.** Add `checkJs` type checking with JSDoc types, plus ESLint and Prettier, and run them in CI. That is 11k lines of untyped JS, and the client is covered only by screenshots.
13. **[UI] Settings panel.** There are no settings. Quality can only be set with `?quality=`. Add volume, quality tier, screen shake and flash toggles, reduced effects, key rebinding and a colorblind palette, and save them with the existing safe `localStorage` helper.
14. **[Graphics] Cast animations and mage identity.** All mages share one model and differ only by team color. Add casting gestures: a staff raise, a hand glow in the school's color, and a recoil when the spell fires. Add hat, robe and staff variants players pick in the lobby, so they can tell mages apart in 8v8.
15. **[UI] Readable auras.** Nameplate aura chips show only initials ("R", "C", "B"). Replace them with an icon for each look (burn, chill, shield, stun…), tinted by school, with a timer ring and details on hover or long-press.
16. **[UI] Results that teach.** The results screen is a table of totals. Add damage and healing over time, a per-spell breakdown, fizzle reasons, parry rate and average chord speed, so players can see what to practice.
17. **[Gameplay] Replays.** The same seed, rules, roster and orders always replay a match, so a whole match fits in a few KB of orders. Record it for a replay viewer, shareable replay links and bug reports.
18. **[Testing] Visual regression in place of overwriting `shots/`.** Each `npm test` rewrites `shots/`, which dirties the tree and catches nothing. Compare screenshots against baselines with a pixel tolerance. Split the tests into a fast `test:unit` and a slower `test:browser`.
19. **[Infra] Deploy and observe.** Add a Dockerfile and graceful shutdown on SIGTERM (finish or notify rooms). Add structured logs and a `/metrics` endpoint (rooms, peers, tick lag, bytes sent). Cap connections per IP and check the WebSocket `Origin`.
20. **[Gameplay] Reasons to come back.** Keep a local profile: match history, mastery per spell (chord speed, fizzle rate) and win/loss by mode. Add a bot ladder that climbs from easy to hard to a new top tier.
